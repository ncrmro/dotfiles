# Exact-path migrations

Installation never searches `$HOME` for stale links. For a rename or deletion,
record the old destination and its old package source here. Inspect and remove
only that exact destination, only when it is a symlink to the recorded source.
Preserve regular files and links to other sources. Run migrations explicitly
before installation when an old link conflicts with a new owner.

Known retired paths:

| Destination under `$HOME` | Former source under this checkout |
| --- | --- |
| `.config/hypr/hyprland.conf` | `packages/hyprland-common/.config/hypr/hyprland.conf` |
| `.config/hypr/ncrmro.conf` | `packages/hyprland-common/.config/hypr/ncrmro.conf` |
| `.config/hypr/host.conf` | `packages/hyprland-HOST/.config/hypr/host.conf` (the selected workstation, laptop, or delltop package) |
| `.config/uwsm/env` | `packages/hyprland-common/.config/uwsm/env` (now generated by Desktop) |
| `.config/keystone/theme-catalogs/user/royal-green/waybar.css` | `packages/themes/.config/keystone/theme-catalogs/user/royal-green/waybar.css` |

For example, from this checkout, using GNU `realpath` (`grealpath` on macOS):

```bash
old="$HOME/.config/hypr/hyprland.conf"
expected="$(pwd -P)/packages/hyprland-common/.config/hypr/hyprland.conf"
if [[ -L "$old" && "$(realpath -m -- "$old")" == "$expected" ]]; then
  rm -- "$old"
fi
```

If the link points into an older worktree, inspect `readlink "$old"` and use
that verified checkout path for `expected`; do not broaden the match to any
symlink or delete the containing directory.

Older theme files also moved from `.config/themes/<theme>/` into the sparse
`.config/keystone/theme-catalogs/user/` catalog. The generated
`.config/themes/current` link belongs to Keystone and must remain untouched.
Use the recorded deletion/rename paths in `git log --name-status --
packages/themes` to identify the particular old theme files installed on a
host. Apply the same exact-source check for each reviewed path. Never traverse
`.config/themes`, `.local/share`, or container storage to discover cleanup
candidates. Old unrelated links need no automatic cleanup during boot.
